# ESLint & Prettier Konfiguration

## Übersicht

Dieses Projekt verwendet ESLint 9 mit Flat Config für TypeScript und React Code-Qualität sowie Prettier für konsistente Code-Formatierung.

## Installierte Packages

### ESLint
- `eslint` (^9.17.0) - Core ESLint
- `@eslint/js` (^9.17.0) - ESLint JavaScript Regeln
- `@typescript-eslint/parser` (^8.21.0) - TypeScript Parser
- `@typescript-eslint/eslint-plugin` (^8.21.0) - TypeScript Regeln
- `eslint-plugin-react` (^7.37.3) - React Regeln
- `eslint-plugin-react-hooks` (^5.1.0) - React Hooks Regeln
- `eslint-plugin-react-refresh` (^0.4.16) - React Refresh Regeln

### Prettier
- `prettier` (^3.4.2) - Code Formatter
- `eslint-plugin-prettier` (^5.2.1) - Prettier als ESLint Regel
- `eslint-config-prettier` (^9.1.0) - Deaktiviert konfliktuelle ESLint Regeln

## Konfigurationsdateien

### eslint.config.js
- Verwendet ESLint 9 Flat Config Format
- Separate Regeln für:
  - TypeScript/React Dateien (src/**)
  - Test Dateien (tests/**, *.test.ts, *-test.ts)
  - Electron Dateien (electron/**)
- Globale Variablen für Browser, Node.js und Electron

### .prettierrc
Prettier Formatierungsregeln:
- Semikolons: Ja
- Quotes: Single Quotes
- Print Width: 80 Zeichen
- Tab Width: 2 Spaces
- Trailing Commas: ES5

### .prettierignore
Ignoriert Build-Outputs, node_modules und generierte Dateien

## NPM Scripts

```bash
# Linting
npm run lint              # ESLint auf gesamtes Projekt
npm run lint:fix          # ESLint mit Auto-Fix

# Formatierung
npm run format            # Formatiert alle Dateien mit Prettier
npm run format:check      # Prüft Formatierung ohne Änderungen
```

## Regeln-Highlights

### TypeScript
- Strict Mode aktiviert
- Keine `any` Types erlaubt (Error)
- Konsistente Type Imports bevorzugt
- Non-null Assertions sind Warnings

### React
- React Hooks Regeln (exhaustive-deps als Warning)
- React Refresh für HMR
- Keine React Imports in JSX benötigt (React 18+)

### Code-Qualität
- `no-console`: Warnung (außer console.warn/error)
  - In Test-Dateien: Erlaubt
  - In Electron-Dateien: Erlaubt
- `no-debugger`: Warnung
- `prefer-const`: Error
- `no-var`: Error

## Bekannte Warnings

Die aktuellen 140 Probleme (29 Errors, 111 Warnings) sind hauptsächlich:

1. **React Hooks exhaustive-deps** (Warnings)
   - Zu prüfen ob Dependencies ergänzt oder Rule disabled werden soll

2. **Console Statements** (Warnings)
   - In src/lib/ballistics/core.ts (Debug/Entwicklung)
   - Sollten vor Production-Release entfernt werden

3. **Non-null Assertions** (Warnings)
   - In src/main.tsx und Stores
   - Code-Review empfohlen

4. **Explicit Any Types** (Errors)
   - In electron/storage.ts und tests/setup.ts
   - Benötigen Type-Definitionen

## Best Practices

1. **Vor Commit**: `npm run lint:fix && npm run format`
2. **CI/CD**: `npm run lint && npm run format:check`
3. **IDE Integration**: VS Code ESLint Extension empfohlen
4. **Pre-Commit Hook**: Husky + lint-staged (optional)

## Troubleshooting

### ESLint findet Dateien nicht
- Prüfe `ignores` Pattern in eslint.config.js
- Stelle sicher, dass Dateien nicht in .prettierignore sind

### TypeScript Parsing Fehler
- Stelle sicher, dass tsconfig.json korrekt ist
- Prüfe `parserOptions` in eslint.config.js

### Prettier konfligiert mit ESLint
- eslint-config-prettier ist installiert und sollte Konflikte vermeiden
- Bei Problemen: `npm run format` vor `npm run lint:fix`
